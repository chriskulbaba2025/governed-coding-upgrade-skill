# Security Policy

## Reporting a security issue

Do not publish sensitive vulnerabilities, secrets, credentials, private repository data, or exploit details in a public issue.

For a private repository, report the issue directly to the repository owner through an approved private channel and identify:

- affected file or component;
- observed security behavior;
- reproduction conditions;
- expected protected behavior;
- whether credentials or external systems may be affected.

Security fixes must use the governed change lifecycle in `SKILL.md`, including frozen scope, direct proof, exact-head verification, independent audit, and release authorization.
