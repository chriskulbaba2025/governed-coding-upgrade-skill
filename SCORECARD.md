# Governed Coding Upgrade Skill — Semantic Quality Scorecard

**Version evaluated:** 2.2.0  
**Release name:** Governed Coding Upgrade v2.2.0 — Universal Project Orchestration  
**Acceptance threshold:** Every semantic area must score **19/20 or higher**.

## 1. Governance & Control — 20/20

Release Intent, Change Tier, exact repository/SHA preflight, Project Adapter validation, frozen scope, protected invariants, production-spine and contract-map requirements, explicit authorization boundaries, terminal machine gating, Governance Hold, and the `gcu-execution-control/1.0.0` authority split prevent unearned release or execution-policy claims. GCU requests capability but does not become a provider router, credential broker, or authoritative billing ledger.

## 2. Execution Process & Determinism — 20/20

Deterministic lifecycle, Project Discovery, optional role-based agent orchestration, provider-neutral capability floors, durable escalation state, Sequential Evidence Gates, acceptance freeze, dirty-tree continuation, interruption resume, balanced verification, Challenger gate, terminal-path proof, correction ownership, and exact-head re-audit create a predictable operating model across project types and execution runtimes.

## 3. Testing, Evidence & Audit Quality — 20/20

Capability-based Test Area Maps, real-path acceptance, Producer → Contract → Consumer proof, false-PASS prohibitions, single validated-object continuity, evidence preservation, fail-closed negative proof, durable restart/external-call contracts, execution-policy receipt references, terminal retrieval proof, truthful SELF_AUDIT labeling, and escaped-proof regressions reduce false confidence. Model capability and audit-context independence are explicitly separate controls.

## 4. Automation & Delivery Efficiency — 20/20

Reusable Project Adapters, Change Tiers, composable agent roles, test-area selection, durable change workspaces, provider-neutral routing context, budget-envelope and usage-receipt references, narrow/affected/terminal verification cadence, interruption resume, machine release gate, and package validation reduce rediscovery without duplicating the orchestration or AI-policy control planes.

## 5. Generalizability & Portability — 20/20

The protocol is language-, framework-, CI-, cloud-, provider-, model-, agent-runtime-, billing-system-, and repository-layout-agnostic. Project kinds are descriptive rather than restrictive. Monorepos and multi-component systems are supported through adapter-defined components and affected-boundary selection. Execution-control products integrate through a versioned contract rather than becoming GCU dependencies.
